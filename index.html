THREE STEPS

  1. DROP AN STL

    Binary or ASCII, up to 150 MB. The file is read from your disk straight into the page.

  2. WATCH IT PATCH

    A worker scans, repairs and re-checks the mesh off the main thread, with a live log of what it finds and fixes.

  3. DOWNLOAD A CLEAN SOLID

    HullPatch only says "watertight" once the fixed file has no open edges, non-manifold edges or flipped faces.

02

WHAT GETS PATCHED

  • HOLES

    Open edges are closed flat where they can be, and with a fan where they can't. Zero-width slivers are stitched into the neighbouring face.

  • INSIDE WALLS

    Paper-thin walls left where parts were joined are taken out, so every edge is shared by exactly two faces.

  • FLIPPED FACES

    Faces are turned to point outward, and cavities inward, so the slicer knows what's solid.

  • SPECKS

    Flat or tiny loose bits that can't print are removed. The real parts are kept.

SEE EXACTLY WHAT WAS WRONG

The result opens in an interactive 3D view with a Before and After toggle. Every problem triangle in the Before view is coloured, and problems too small to spot get a marker.

  • See inside makes the healthy surface see-through, so walls hidden in the model show up.
  • Orbit, zoom, and jump to Top, Front and Side views.
  • The viewer is F3D's WebAssembly build, loaded only once a repair starts.

YOUR FILE STAYS YOUR FILE

There is no server to upload to. The repair runs in a Web Worker in the tab and the 3D view runs in the page, so a model you haven't released never leaves your machine.

  • No account, no analytics, no upload.
  • The repaired file is checked again before download.
  • Each repair stops after 4 minutes so your browser stays responsive.
THE REPAIR, IN SIX MOVES
1 Merge corners that sit in one place
2 Drop degenerate and duplicate faces
3 Make neighbours agree on winding
4 Fill holes, stitching slivers
5 Remove non-manifold faces, refill
6 Clear specks under 1/1000 of the model

SELF-HOST IN ONE COMMAND

HullPatch ships as a tiny container: non-root nginx serving static files. It needs no settings or volumes and runs fine read-only, because repairs happen in the visitor's browser.

Multi-arch images (amd64 and arm64) are published to GHCR on every push to main.

DOCKER
# then open http://localhost:8080
docker run -d --name hullpatch \
  -p 8080:8080 \
  ghcr.io/hibikipr/hullpatch:latest
03

FAQ

Is my file uploaded anywhere?

No. The repair runs in a worker inside the browser tab, and the 3D view runs in the page. Your STL is read from your disk and the fixed copy is handed straight back to you.

Will it change the shape of my model?

Only where it has to. Holes are closed with new faces, inside walls and duplicate faces are taken out, and loose bits that are flat or tiny are removed. The result is only kept when the model's volume stays the same.

Does it work with Bambu Studio?

That's what it's built for. After the repair, HullPatch checks the file for the three problems Bambu Studio reports: open edges, non-manifold edges and flipped faces.

What if my file is too broken?

Files up to 150 MB are accepted, and each repair stops after 4 minutes. If a repair is stopped or comes back partly repaired, the log says what is left so you know where to look.

What does it cost?

Nothing. HullPatch is free and open source, part of townsville.cc.
